# Signed model approval and verified cache

PR-51 adds an executable local catalog and cache boundary. It does not enable a public model marketplace, download from arbitrary URLs, approve a third-party license, or seed model files to peers. The existing manifest remains an integrity receipt. A separate signed catalog record supplies an explicit publisher assertion and purpose-specific rights; an owner-controlled trust root decides which publishers and model digests may be used.

The repository's existing MIT license remains unchanged. Its conflict with earlier Cargo license metadata remains an owner decision described in [provenance](upstream-provenance.md). A model license string is an assertion to review; code never turns that string into a grant automatically. Each boolean permission defaults to false in Rust, and serialized records must include all three booleans explicitly.

## Record and trust contract

`SignedModelRecord` has version 1, publisher PeerId, protobuf Ed25519 public key, issue/expiry Unix seconds, status (`approved`, `disabled`, `revoked`), license assertion, `ModelRights`, provenance, complete `ModelManifest`, and signature bytes. Its signing transcript is the exact UTF-8 domain `synapse-model-catalog-v1\0` followed by compact serde JSON in that struct's declared field order, with `manifest.artifacts` sorted lexically by filename and `signature` an empty array. The public `signing_bytes()` method defines the encoding. All approval fields and every manifest artifact are signed.

`inspect_record` requires an explicitly enrolled, matching Ed25519 key; valid signature; approved status; unrevoked publisher and canonical model digest; unexpired record; no issue time more than five seconds in the future; and permission for the selected purpose. A record lasts at most 366 days. Model manifest validation rejects unsafe filenames, missing required files, duplicate names and conflicting sizes for one content digest. JSON reads are limited to 4 MiB. Trust policies allow at most 64 publishers, 4,096 publisher revocations and 10,000 model revocations.

`TrustRoot::default()` trusts nobody. `read_trust_root` also rejects policy files writable by another account/group, symlinks, and unprotected or foreign-controlled path ancestors. It accepts a policy owned by the current user or root. Receiving a key from a worker or finding it beside downloaded model files does not enroll it. Signing-key custody, authentic policy distribution, review and rotation remain owner responsibilities; there is no built-in production signing key.

Every `verify_model` call reevaluates current policy, expiry and every artifact byte. Revocation therefore stops new acquisitions. A `PinnedModel` already held by a running backend remains a filesystem pin until its caller releases it; stopping a running job after an emergency revocation requires the daemon's cancellation path. The cache does not claim to cancel inference itself.

## Filesystem and resource behavior

The cache is a private directory with `objects`, `models`, `staging` and `pins` subdirectories and a recognized format marker. It refuses to adopt an unrelated nonempty directory. Initial support requires Unix permission and `flock` semantics on a local filesystem; the implementation is tested on Linux. Network filesystems, hostile same-account processes, disk-failure durability and other platforms need separate qualification.

Imports accept regular local artifact files in a protected source directory. They reject parent traversal and symlink components, final symlinks, special files, unmanifested shard references, missing artifacts, incorrect sizes and incorrect SHA-256 hashes. A Hugging Face snapshot commonly contains symlinks: make an explicit regular-file copy of the pinned, reviewed files first. No source file is executed, and the cache has no URL fetch operation.

The importer reserves capacity under an exclusive process lock, streams each new object in 64 KiB chunks into private files, checks the expected size and hash, flushes files, makes objects read-only, and creates a model view using hard links to content-addressed objects. It verifies the complete manifest before publishing objects and atomically renaming the complete model directory on the same filesystem. Parent directories are flushed. Duplicate bytes share a single object, including across different revisions. A corrupt existing object is rejected and never silently replaced.

The quota counts logical unique artifact bytes, including newly staged unique objects. It does not pretend to measure filesystem block overhead, JSON metadata, unrelated download directories, or physical RAM. Metadata and entry counts are separately bounded: at most 100,000 objects and 10,000 model views. Lowering a quota does not delete an existing cache automatically; call `prune` explicitly. Orphaned objects left by interruption count toward the quota until pruning. Staging cleanup runs under the same writer lock, and no partially verified model view is published.

`verify_model` returns a `PinnedModel` holding a shared OS lock. Keep it alive for the full time a backend accesses its directory. Pruning takes an exclusive nonblocking lock per model, skips active pins, removes least-recently-used unpinned views, then deletes objects with no remaining model links. The result reports actual remaining bytes and blocked pins; it does not claim that a target was reached when active models prevent it. Process exit releases the lock without a stale PID cleanup guess. Callers that discard the pin while still using the path violate this lifecycle contract.

## Executable local workflow

The example is a real caller of the same exported core functions. It needs no network and adds no trust to global application state. Its fixture command creates only original synthetic cache-test bytes and a private local test signing key in a **new** directory.

```sh
cargo build -p synapse-core --example catalog --locked --offline
cargo run -p synapse-core --example catalog --locked --offline -- fixture /absolute/new/catalog-fixture
cargo run -p synapse-core --example catalog --locked --offline -- inspect /absolute/new/catalog-fixture/record.json /absolute/new/catalog-fixture/trust.json local
cargo run -p synapse-core --example catalog --locked --offline -- import /absolute/new/catalog-fixture/source /absolute/new/catalog-fixture/record.json /absolute/new/catalog-fixture/trust.json /absolute/new/catalog-fixture/cache 1048576 local
```

The import prints a real `manifest_digest` and cache directory. Use that digest with `verify`; the one-shot command releases its pin when it exits:

```sh
cargo run -p synapse-core --example catalog --locked --offline -- verify PRINTED_DIGEST /absolute/new/catalog-fixture/trust.json /absolute/new/catalog-fixture/cache 1048576 local
cargo run -p synapse-core --example catalog --locked --offline -- prune /absolute/new/catalog-fixture/cache 1048576 0
```

Replacing `local` with `host` or `redistribute` for the generated fixture fails because those permissions were not granted. Production callers can use `SignedModelRecord::sign` with an explicitly authorized publisher identity and an independently reviewed policy; the example does not contain a generic “approve any model” switch.

### Main application commands

The built `synapse` application exposes the same policy and cache operations. Trust roots, purpose and cache quotas are explicit; the commands do not enroll publishers globally. For a reproducible original inference fixture, run the example's `inference-fixture NEW_DIRECTORY` command instead of `fixture`. Then use the main application:

```sh
synapse catalog inspect --record /absolute/private/fixture/record.json --trust-root /absolute/private/fixture/trust.json --purpose local
synapse catalog import --source /absolute/private/fixture/source --record /absolute/private/fixture/record.json --trust-root /absolute/private/fixture/trust.json --purpose local --cache /absolute/private/fixture/cache --quota-bytes 1048576
synapse catalog verify --digest PRINTED_DIGEST --trust-root /absolute/private/fixture/trust.json --purpose local --cache /absolute/private/fixture/cache --quota-bytes 1048576
synapse catalog infer --digest PRINTED_DIGEST --trust-root /absolute/private/fixture/trust.json --cache /absolute/private/fixture/cache --quota-bytes 1048576 --prompt '<s> </s> Hello' --max-tokens 8
synapse catalog prune --cache /absolute/private/fixture/cache --quota-bytes 1048576 --target-bytes 0
```

`catalog infer` always checks local-inference rights and retains the returned OS cache pin through backend loading, bounded generation and unloading. A separate `verify` invocation releases its pin when it exits; its output is not a long-lived authorization token. Inference uses the existing raw-prompt local backend, so supply a model-appropriate prompt. GUI publisher enrollment and automatic third-party approval are not provided.

The core integration points are `inspect_record`, `read_trust_root`, `ModelCache::open`, `import_model`, `verify_model`, and `prune`. CLI availability and signed records remain subject to runtime architecture, tokenizer, template, memory admission and numerical checks. Aggregate main-application evidence is recorded in [the final tranche report](evidence/final-tranche.md).

## Verification and remaining gates

```sh
cargo test -p synapse-core --lib --locked --offline catalog::tests
python3 schemas/check_catalog.py --source-root .
```

The initial 21 catalog tests passed locally. Three later lock-lifetime regressions also pass in the final 24-test catalogue subset; see [the lock evidence](evidence/catalog-lock-lifetime.md). They exercise real Ed25519 signatures, filesystem writes, hard links, advisory locks, quotas, cache corruption, rights denial, revocation, expiry, hostile paths/symlinks/FIFOs, interrupted stages, deduplication, and pinned pruning. The contract check adds JSON shapes, exact canonical signing bytes, eight invalid fixtures, and an independent OpenSSL verification of the Rust-generated public golden fixture. Its private test key was discarded; the golden record's issue time is its test clock, not a claim of current approval. The check runs in the security/contracts workflow.

The six executed CLI steps are recorded in [local evidence](evidence/catalog-cache-local.json) and [captured output](evidence/catalog-cache-cli-output.json): fixture, inspection, import, verification, denied hosting and prune. They imported 59 unique artifact bytes and pruned back to zero. These checks use original synthetic content and local temporary directories. They do not establish production key governance, reviewed third-party rights, downloaded-model compatibility, WAN distribution, independent security acceptance, or a released package. Planned PR numbers identify local work packages; no GitHub PR publication is implied.
