# PR-52: Verify local packages and make version switching recoverable

Local draft for planned review ref `review/pr-52`. This file does not open a GitHub PR or grant acceptance. Review refs are chronological integration boundaries; related follow-ups can occur in later entries of the stack.

## Problem and scope

Installation and updates must not require broad privileges, activate corrupt bytes or remove a running worker/foreign data. Provide verifiable local packages, staged activation, rollback and narrowly owned cleanup.

## Changes and non-goals

- Add deterministic bounded package creation and Ed25519 statements in `scripts/release/package.py`/`package_format.py`, with explicit development versus signed candidate policy.
- Implement checksum/signature validation, safe manual extraction, private staged releases, atomic current pointer, verified rollback and active-process protection in `install.py`.
- Later review hardens ancestor/managed-directory permissions and snapshots source binary/SBOM bytes before hashing/archive creation; package CI and tests cover those races.

## Security, privacy and compatibility impact

No sudo, service launch or shell-profile edits; hostile archives, symlinks/traversal, wrong targets and foreign managed files are rejected. Production trust keys are explicit; unsigned development requires a distinct opt-in and checksum.

## Rollback, migration and known limitations

Activation is one atomic current-pointer switch; previous-version metadata is a separate operation. A power interruption between pointers can require manual selection of a retained verified version. Do not delete identities/models/config outside the managed installation.
