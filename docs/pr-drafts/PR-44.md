# PR-44: Bound wire decoding, quotas and relay exhaustion

Local draft for planned review ref `review/pr-44`. This file does not open a GitHub PR or grant acceptance. Review refs are chronological integration boundaries; related follow-ups can occur in later entries of the stack.

## Problem and scope

An authenticated or unauthenticated peer can still exhaust memory/time with hostile frames or identity churn. Bound framing, decoding, decompression, shared traffic and relay resources before expensive work.

## Linked plan IDs / ADR / dependency PRs

[Master plan](../MASTER_PLAN.md), PR-44; dependency packages: [15](PR-15.md), [39](PR-39.md), [42](PR-42.md). [Scope/evidence ADR](../adr/0001-scope-and-evidence.md). A local implementation boundary does not waive physical, owner or release prerequisites.

## Changes and non-goals

- Enforce marker/length/variant limits, strict bincode trailing-data rejection, aggregate decode reservations and frame deadlines in `network/codec.rs`/`protocol.rs`.
- Bound LZ4/Zstd expansion and validate tensor shape/size; add per-peer and shared message/byte windows in `network/quota.rs` and apply them to requests and responses.
- Add golden/malformed corpus tests and a later real one-slot relay reservation-exhaustion case in `tests/private_transport.rs`.

This draft describes the integrated behavior attributable to PR-44; inspect the stack manifest for the exact diff and later cross-cutting follow-ups. Remaining acceptance is listed below.

## Security, privacy and compatibility impact

Controls are limited to 64 KiB; permitted data frames to 64 MiB plus 4,096 bytes; frame reads/writes have 15-second deadlines. Limits are independent of job admission and do not establish a denial-of-service audit.
