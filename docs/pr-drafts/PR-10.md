# PR-10: Admit model-shaped memory and report measured capability

Local draft for planned review ref `review/pr-10`. This file does not open a GitHub PR or grant acceptance. Review refs are chronological integration boundaries; related follow-ups can occur in later entries of the stack.

## Problem and scope

Rounded RAM labels and generic per-layer guesses can admit an impossible model or misreport GPU capability. Reserve the actual execution dtype, context and scratch needs before loading.

## Linked plan IDs / ADR / dependency PRs

[Master plan](../MASTER_PLAN.md), PR-10; dependency packages: [07](PR-07.md), [09](PR-09.md). [Scope/evidence ADR](../adr/0001-scope-and-evidence.md). A local implementation boundary does not waive physical, owner or release prerequisites.

## Changes and non-goals

- Add `inference/memory.rs` and integrate exact weight/KV/GQA/context/scratch/load reservations into planning, preparation and CLI doctor.
- Use initialized backend capability and real microprobes in `hardware.rs`/`compute_score.rs`; do not infer GPU speed from a device label.
- Bound verification logits/context and account for CPU F32 execution of half-stored checkpoints; related fixes land with PR26 and later integration.
