# PR-42: Apply acknowledged worker controls and native process caps

Local draft for planned review ref `review/pr-42`. This file does not open a GitHub PR or grant acceptance. Review refs are chronological integration boundaries; related follow-ups can occur in later entries of the stack.

## Problem and scope

A configured pause or memory number is not enforcement. Give the worker a real control state machine with acknowledgements and provide an explicit Linux kernel limit for dedicated worker processes.

[Master plan](../MASTER_PLAN.md), PR-42; dependency packages: [07](PR-07.md), [13](PR-13.md), [41](PR-41.md). [Scope/evidence ADR](../adr/0001-scope-and-evidence.md). A local implementation boundary does not waive physical, owner or release prerequisites.

## Changes and non-goals

- Implement worker resource/control policy in `network/worker.rs` with bounded command/acknowledgement plumbing.
- Apply pause, resume, drain and stop in real node transport control and report actual released/active state.
- Expose dedicated CLI `RLIMIT_AS` lowering through later integration, distinct from model admission and GUI process behavior.

This draft describes the integrated behavior attributable to PR-42; inspect the stack manifest for the exact diff and later cross-cutting follow-ups. Remaining acceptance is listed below.

## Security, privacy and compatibility impact

Control authority remains with the authenticated local owner/session. RLIMIT_AS constrains virtual address space, including mappings; it is irreversible within that process and is not a portable resident-RAM, disk, network or GPU sandbox.
