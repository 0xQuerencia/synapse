# PR-41: Protect persistent device identity and revocation state

Local draft for planned review ref `review/pr-41`. This file does not open a GitHub PR or grant acceptance. Review refs are chronological integration boundaries; related follow-ups can occur in later entries of the stack.

## Problem and scope

Identity keys and revocations must survive restart without races, unsafe permissions or lost concurrent updates. Establish a private, atomic filesystem boundary for device proofs and security-state persistence.

## Linked plan IDs / ADR / dependency PRs

[Master plan](../MASTER_PLAN.md), PR-41; dependency packages: [06](PR-06.md), [39](PR-39.md). [Scope/evidence ADR](../adr/0001-scope-and-evidence.md). A local implementation boundary does not waive physical, owner or release prerequisites.

## Changes and non-goals

- Harden `identity.rs` with bounded no-follow reads, owned private permissions, exclusive creation and atomic durable publication.
- Bind public-key signatures to the claimed transport PeerId and provide explicit identity-path APIs for test/process isolation.
- Persist revocation under a lock with reload/merge behavior; later callers reuse the same safe storage primitives for GUI tokens and protocol state.

This draft describes the integrated behavior attributable to PR-41; inspect the stack manifest for the exact diff and later cross-cutting follow-ups. Remaining acceptance is listed below.

## Security, privacy and compatibility impact

Existing corrupt/insecure keys are rejected and preserved, not silently regenerated. Concurrent creation converges, and concurrent revocation cannot lose an already durable denial.
