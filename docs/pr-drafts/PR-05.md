# PR-05: Require complete feasible layer routes

Local draft for planned review ref `review/pr-05`. This file does not open a GitHub PR or grant acceptance. Review refs are chronological integration boundaries; related follow-ups can occur in later entries of the stack.

## Problem and scope

A route must cover every transformer layer exactly once and fit each participant, including coordinator IO. Remove incomplete prefix/overflow allocation and fail explicitly when capacity is insufficient.

## Linked plan IDs / ADR / dependency PRs

[Master plan](../MASTER_PLAN.md), PR-05; dependency packages: [03](PR-03.md), [04](PR-04.md). [Scope/evidence ADR](../adr/0001-scope-and-evidence.md). A local implementation boundary does not waive physical, owner or release prerequisites.

## Changes and non-goals

- Centralize exact contiguous coverage and capacity validation in `shard.rs`.
- Use the validated route in `network/node/generation.rs` instead of silently continuing with uncovered layers.
- Keep planner invariants reusable by later model-shaped memory and topology-aware routing.

This draft describes the integrated behavior attributable to PR-05; inspect the stack manifest for the exact diff and later cross-cutting follow-ups. Remaining acceptance is listed below.

## Security, privacy and compatibility impact

Unknown, zero or insufficient capacity cannot authorize a partial route. No hidden full-model fallback may defeat a configured memory budget.
