# PR-43: Reserve capacity atomically and isolate admitted state

Local draft for planned review ref `review/pr-43`. This file does not open a GitHub PR or grant acceptance. Review refs are chronological integration boundaries; related follow-ups can occur in later entries of the stack.

## Problem and scope

Concurrent preparation and stale cache traces must not exceed capacity or share request state. Reserve before load, bind ownership and release reliably on error, expiry or cancellation.

## Linked plan IDs / ADR / dependency PRs

[Master plan](../MASTER_PLAN.md), PR-43; dependency packages: [06](PR-06.md), [07](PR-07.md), [40](PR-40.md). [Scope/evidence ADR](../adr/0001-scope-and-evidence.md). A local implementation boundary does not waive physical, owner or release prerequisites.

## Changes and non-goals

- Add atomic capacity leases and ownership validation in `inference/admission.rs`.
- Integrate reservation into prepare/load/ready/release and actual node handlers before weight allocation.
- Enforce session/epoch-scoped KV ownership, expected compute cursor and duplicate/reset rejection; unsupported distributed speculation fails closed.

This draft describes the integrated behavior attributable to PR-43; inspect the stack manifest for the exact diff and later cross-cutting follow-ups. Remaining acceptance is listed below.

## Security, privacy and compatibility impact

Admission is not a capability advertisement. The worker verifies owner/session/model/range/epoch and cannot reuse another session cache or bypass capacity via overlapping preparations.
