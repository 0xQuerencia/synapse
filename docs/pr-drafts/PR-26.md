# PR-26: Validate quantized storage and explicit CPU execution

Local draft for planned review ref `review/pr-26`. This file does not open a GitHub PR or grant acceptance. Review refs are chronological integration boundaries; related follow-ups can occur in later entries of the stack.

## Problem and scope

GGUF defaults, unchecked extents and storage dtype assumptions can load an incompatible model or understate memory. Qualify specific formats with numerical comparisons and reject unsupported metadata before allocation.

## Linked plan IDs / ADR / dependency PRs

[Master plan](../MASTER_PLAN.md), PR-26; dependency packages: [09](PR-09.md), [12](PR-12.md), [20](PR-20.md). [Scope/evidence ADR](../adr/0001-scope-and-evidence.md). A local implementation boundary does not waive physical, owner or release prerequisites.

## Changes and non-goals

- Add bounded GGUF header/extent/shape/type/architecture/scaling validation in `inference/gguf_validation.rs` and connect it to pipeline loading.
- Exercise synthetic F32, Q8_0 and Q4_0 full/sliced prefill plus eight decode steps, tied output-head behavior and F32 GGUF/safetensors parity.
- Convert half-stored safetensors explicitly to F32 on CPU and account for execution/load memory; preserve actual format error bounds and loaded tensor sizes in evidence.
