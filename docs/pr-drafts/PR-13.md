# PR-13: Bind private pairing and invitation proofs to identities

Local draft for planned review ref `review/pr-13`. This file does not open a GitHub PR or grant acceptance. Review refs are chronological integration boundaries; related follow-ups can occur in later entries of the stack.

## Problem and scope

A reusable static pairing hash or an unbound invitation can authorize a different peer/session. Bind mutual proof to the authenticated coordinator/worker identities, protocol and fresh challenge, and provide explicit recipient-bound invitation primitives.

## Changes and non-goals

- Replace static proof with normalized-secret HMAC-SHA256 plus role-specific signatures in `pairing.rs` and `protocol.rs`.
- Enforce challenge age/future skew and consume pending attempts; synchronize breaking codec negotiation.
- Add signed expiring private invites and durable single-use redemption APIs; real application joins continue to use mutual pairing.

This draft describes the integrated behavior attributable to PR-13; inspect the stack manifest for the exact diff and later cross-cutting follow-ups. Remaining acceptance is listed below.

## Security, privacy and compatibility impact

Proofs bind peer IDs, nonce, timestamp and protocol with unambiguous encoding. Rate limits and revocation remain separate enforcement; this construction is not a PAKE for arbitrary low-entropy user passwords.
