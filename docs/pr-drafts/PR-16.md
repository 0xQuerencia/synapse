# PR-16: Correlate bounded transport with the active inference session

Local draft for planned review ref `review/pr-16`. This file does not open a GitHub PR or grant acceptance. Review refs are chronological integration boundaries; related follow-ups can occur in later entries of the stack.

## Problem and scope

Late, duplicate or unrelated responses must not mutate the current token/session state. Tie each pending exchange to its expected peer/type/epoch and fail bounded output safely under timeout or backpressure.

## Linked plan IDs / ADR / dependency PRs

[Master plan](../MASTER_PLAN.md), PR-16; dependency packages: [12](PR-12.md), [15](PR-15.md), [44](PR-44.md). [Scope/evidence ADR](../adr/0001-scope-and-evidence.md). A local implementation boundary does not waive physical, owner or release prerequisites.

## Changes and non-goals

- Implement bounded pending requests and response lookup in `network/stream.rs`.
- Apply request/peer/kind/session/epoch/trace correlation in real node handlers and `network/node/transport_control.rs`.
- Connect cancellation, disconnect cleanup, quota checks and acknowledged worker control channels to the event loop; later API follow-ups preserve terminal stream failures.

This draft describes the integrated behavior attributable to PR-16; inspect the stack manifest for the exact diff and later cross-cutting follow-ups. Remaining acceptance is listed below.

## Security, privacy and compatibility impact

Unknown responses cannot advance generation, failed sends do not expose tensor payloads in logs, and timeout/cancel removes only owned state. Worker-control success requires an actual acknowledgement.
