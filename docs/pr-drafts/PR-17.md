# PR-17: Persist epochs and bound recovery progress

Local draft for planned review ref `review/pr-17`. This file does not open a GitHub PR or grant acceptance. Review refs are chronological integration boundaries; related follow-ups can occur in later entries of the stack.

## Problem and scope

After restart or worker loss, stale state and duplicated displayed tokens must not be accepted as new work. Add durable monotonic epochs and an explicit, bounded recovery state model.

## Linked plan IDs / ADR / dependency PRs

[Master plan](../MASTER_PLAN.md), PR-17; dependency packages: [08](PR-08.md), [13](PR-13.md), [16](PR-16.md), [43](PR-43.md). [Scope/evidence ADR](../adr/0001-scope-and-evidence.md). A local implementation boundary does not waive physical, owner or release prerequisites.

## Changes and non-goals

- Add `EpochCounter`, session transitions, accepted-output progress and bounded replay rules in `network/session.rs`.
- Use durable epochs in real assignment preparation and signed readiness sequencing.
- Keep loss handling explicit: the current inference path may fail generation safely; the state model does not imply seamless resumed distributed inference.

This draft describes the integrated behavior attributable to PR-17; inspect the stack manifest for the exact diff and later cross-cutting follow-ups. Remaining acceptance is listed below.

## Security, privacy and compatibility impact

Epoch persistence uses the private-state boundary; corruption fails closed. No prompt/token history is silently persisted to manufacture restart recovery, and old owners/epochs cannot commit new output.
