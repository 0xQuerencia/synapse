# PR-21: Serve the authenticated compatible chat subset

Local draft for planned review ref `review/pr-21`. This file does not open a GitHub PR or grant acceptance. Review refs are chronological integration boundaries; related follow-ups can occur in later entries of the stack.

## Problem and scope

Clients need a real, bounded interface with explicit compatibility and errors. Add local model listing and chat completion streaming while rejecting unsupported provider features rather than silently ignoring them.

## Linked plan IDs / ADR / dependency PRs

[Master plan](../MASTER_PLAN.md), PR-21; dependency packages: [19](PR-19.md), [20](PR-20.md), [39](PR-39.md). [Scope/evidence ADR](../adr/0001-scope-and-evidence.md). A local implementation boundary does not waive physical, owner or release prerequisites.

## Changes and non-goals

- Add `GET /v1/models` and `POST /v1/chat/completions` in `compatible_api.rs`, connected to the Candle backend.
- Support model/messages/max_tokens/temperature=0/stream/include_usage, stable errors, bounded SSE and terminal completion; raw mode takes one user message.
- Enforce loopback, local credential-file login, Host/Origin and body limits in GUI auth/main; later backpressure fixes deliver terminal failure before `[DONE]`.

This draft describes the integrated behavior attributable to PR-21; inspect the stack manifest for the exact diff and later cross-cutting follow-ups. Remaining acceptance is listed below.

## Security, privacy and compatibility impact

No credential URLs or automatic remote fallback; unsupported tools/images/sampling fields fail explicitly. The local admin token is not hosted multi-tenant authorization or a billing credential.
