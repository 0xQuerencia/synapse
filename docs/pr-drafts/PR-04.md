# PR-04: Define supported Llama numerics and prompt behavior

Local draft for planned review ref `review/pr-04`. This file does not open a GitHub PR or grant acceptance. Review refs are chronological integration boundaries; related follow-ups can occur in later entries of the stack.

## Problem and scope

Broad model names and generic prompt wrapping obscured the actual supported architecture and numerical assumptions. Validate configuration and token semantics before presenting a model as usable.

## Linked plan IDs / ADR / dependency PRs

[Master plan](../MASTER_PLAN.md), PR-04; dependency packages: [03](PR-03.md). [Scope/evidence ADR](../adr/0001-scope-and-evidence.md). A local implementation boundary does not waive physical, owner or release prerequisites.

## Changes and non-goals

- Validate Llama dimensions, grouped-query attention, context, RoPE and supported configuration in `inference/pipeline.rs`.
- Use correct RMS computation and explicit EOS/tokenizer behavior in the inference and tokenizer paths.
- Define model-family prompt formatting and raw-prompt behavior in `inference/prompt_format.rs`; independent fixtures arrive through PR40.
- Later checkpoint-semantics follow-up rejects unsupported activation, RoPE, tensor-parallel and quantized-safetensors assumptions before loading; absent KV-head count defaults to ordinary attention.

This draft describes the integrated behavior attributable to PR-04; inspect the stack manifest for the exact diff and later cross-cutting follow-ups. Remaining acceptance is listed below.

The final follow-up also gives ordinary and accepted speculative tokens one bounded upstream text decoder, with multi-token UTF-8, turn-isolation and error regressions. Actual GUI text matches the local API in final process evidence.

## Security, privacy and compatibility impact
