# PR-14: Make discovery conservative, pinned and bounded

Local draft for planned review ref `review/pr-14`. This file does not open a GitHub PR or grant acceptance. Review refs are chronological integration boundaries; related follow-ups can occur in later entries of the stack.

## Problem and scope

Bootstrap addresses and discovery hints must not become authorization, leak private pool state or grow an unlimited peer cache. Make discovery opt-in and validate identity-bound candidates.

## Linked plan IDs / ADR / dependency PRs

[Master plan](../MASTER_PLAN.md), PR-14; dependency packages: [11](PR-11.md), [13](PR-13.md). [Scope/evidence ADR](../adr/0001-scope-and-evidence.md). A local implementation boundary does not waive physical, owner or release prerequisites.

## Changes and non-goals

- Validate bootstrap/relay configuration and pinned peer-address relationships in `netconfig.rs`.
- Bound cached peers/addresses and reject unpinned or malformed entries in `network/peer_cache.rs`.
- Connect policy to lifecycle/handlers; later follow-up disables the DHT service itself unless explicitly configured, with LAN discovery also off by default.

This draft describes the integrated behavior attributable to PR-14; inspect the stack manifest for the exact diff and later cross-cutting follow-ups. Remaining acceptance is listed below.

## Security, privacy and compatibility impact

An address hint still requires mutual authentication and membership checks. DNS/address parsing does not authorize arbitrary peers or publish prompts, secrets or balances.
